# OGRE 14 authenticated source-texture receipts

Status: implemented capture/lifecycle and authenticated OGRE-native extraction
boundary; consumption by the live Ogre-Next material coordinator remains a
separate scene-wiring step.

## Contract

`Ogre14AuthenticatedTextureReceipt` owns an immutable copy of the exact source
bytes selected for one OGRE texture load. Receipt version 1 binds all of the
following without case folding or filename inference:

- effective resource group and its globally monotonic generation;
- exact authenticated source-archive identity, globally unique synthetic
  `Ogre::Archive` name, type, pointer token, and lowercase archive SHA-256;
- exact case-sensitive archive member and exact OGRE resource name;
- pre-load resource pointer token, handle, and `getStateCount()`, or one
  caller-minted pre-resource token when no resource exists yet;
- source byte count and SHA-256;
- every legacy DDS header field, plus the five DX10 extension fields when the
  bytes carry the `DX10` FourCC; and
- for generated compatibility textures, the authorizing archive SHA-256 and
  exact rule `ror-legacy-material-procedural-dds-v1`, version 1.

DDS facts come from the bytes, never from a `.dds` suffix. A truncated or
structurally invalid DDS header fails closed. Non-DDS source data is recorded as
`NOT_DDS` and still retains byte-exact identity.

## OGRE loading edge

`LoadAndVerifyTerrainBundleArchiveSnapshot()` opens a dependency archive once,
enforces the 512 MiB ceiling, hashes the bytes it actually read, and publishes
one immutable snapshot only when the authored lowercase SHA-256 matches. The
snapshot, not its mutable source pathname, is registered through OGRE's
`EmbeddedZip` factory under a globally unique synthetic name. Registration
cross-checks the resource-group location and `ArchiveManager` iterator against
the same name, type, read-only flag, and pointer. The immutable owner remains
alive through group teardown. No authenticated dependency is ever reopened from
disk after verification.

`ContentManager::resourceLoading()` mirrors OGRE's first-location selection.
For textures it enumerates each archive's bounded index and reconstructs the
case-sensitive member as `FileInfo::path + FileInfo::basename`. Exact or
case-folded full-name collisions are rejected; non-strict ZIP basename fallback
is accepted only when it identifies one member. The chosen archive is then
required to match the pointer-exact authenticated registration before that exact
member is opened once.

The selected member stream is copied and hashed, an immutable receipt is built,
and a replacement `Ogre::MemoryDataStream` is constructed from the
receipt-owned bytes. OGRE receives only that replacement. The texture path
never reopens by resource name or `AUTODETECT`. Existing authenticated mesh
behavior remains separate and unchanged.

Generated legacy-material fallbacks use the same replacement-stream rule. Their
receipt records the compatibility authority and rule/version instead of
pretending that generated bytes came from an archive member.

The receipt is committed only after the replacement stream has been allocated
and after group generation, archive authority and pointer, resource pointer,
handle, name, and ownership are revalidated under the content-manager state
lock. OGRE increments `Resource::getStateCount()` only after its later
decode/upload succeeds, so an exact same-state, same-bytes, same-provenance
retry is idempotent. Any other same-state duplicate remains a closed failure.

## Already-loaded texture resolution

A plain `Ogre14AuthenticatedTextureReceipt` is source evidence, not live
registry authority: public `BuildOgre14AuthenticatedTextureReceipt()` can
construct an identical value outside `ContentManager`. The native extractor
therefore accepts only an opaque
`Ogre14AuthenticatedTextureResolution` minted through the registry's private
`ContentManager` bridge. A resolution retains the exact source-receipt control
block and exact immutable registry snapshot and binds the active group
generation, `ContentManager` resolver instance, Texture pointer, handle, name,
group, and loaded state count. Copying the resolution preserves those control
blocks. Reboxing bytes/metadata, using an equivalent synthetic registry, or
substituting another resolver does not.

Pinned OGRE 14.5.2 establishes the only accepted state transition:
`Resource::load()` records the source while the resource is `LOADING`, then a
successful decode/upload stores `LOADED` and calls `_dirtyState()` exactly
once. `unload()` does not increment the counter, a failed load resets to
`UNLOADED` without incrementing it, and `reload()` is one unload plus one load.
Consequently, a receipt captured at pre-load state `n` resolves only when the
already-loaded Texture is at checked state `n + 1`. Overflow, `n`, any state
above `n + 1`, manual dirtying, reload without a replacement receipt, or a
non-loaded resource fails closed.

`ContentManager::ResolveAuthenticatedTexture()` additionally requires the
active `TextureManager`, resource type `Texture`, exact creator, and exact
handle and name/group manager indices to resolve back to the same pointer. It
re-observes all live identity after the allocating mint before publishing the
resolution. The no-throw final revalidation repeats those ownership checks and
requires the exact current registry snapshot. Strict v1 snapshot binding means
even an unrelated registry publication invalidates an older proof; a fresh
resolve succeeds if the texture's own receipt is still current.
Neither operation performs an archive lookup or reopen: both inspect only the
already-loaded TextureManager indices and committed immutable registry state.

The authenticated native extractor performs GPU readback first, resolves the
exact `TextureUnitState::_getTexturePtr()` it read, retains one resolution per
captured texture, reacquires that exact TUS pointer, and calls the same resolver
for final revalidation immediately before output publication. The legacy
capture overload remains available but deliberately leaves the resolution
vector empty, so GPU pixels cannot be mistaken for authenticated source bytes.
Untextured captures remain valid with an empty vector.

OGRE's `mStateCount` is a plain `size_t`, not an atomic. Its pinned source even
allows lost concurrent dirty increments, and OGRE exposes no public Resource
lock spanning texture readback. Resolve, native readback, and final
revalidation must therefore run on the serialized OGRE resource/render thread.
The ContentManager mutex makes registry snapshot access thread-safe; it does
not claim to make concurrent OGRE reload/readback valid.

## Lifecycle and limits

The registry is an immutable snapshot with hard ceilings of 65,536 live
receipts, 65,536 retained group records, 512 MiB per source, 1 GiB retained
source bytes, and 16 MiB of retained identity strings. Authenticated archives
have the same 512 MiB per-snapshot and 1 GiB retained-owner ceilings. A
process-wide 65,536-attempt ceiling bounds OGRE's `EmbeddedZip` registration
table even across failed mounts.

Every package registration, resource-group scripting reset, and package-group
teardown advances one process-wide 64-bit generation. Mount builds all
allocation-bearing map, generation, mesh, and receipt candidates before
exposing `EmbeddedZip`; after its exact pointer is known, state is published
only through operations whose exact compiled container/snapshot types are
guarded by `noexcept`/nothrow-destructor static assertions. The temporary owner
node is extracted before the first publication swap, so no potentially
throwing erase follows publication. A failed mount removes the OGRE location
and its pending owner while leaving the prior ContentManager generation and
maps unchanged. If that removal cannot prove both the ArchiveManager location
and EmbeddedZip factory entry absent, the immutable pending owner is retained
and the process terminates. This is intentionally not a recoverable group state:
returning could let an unproven synthetic archive shadow a later load or retry,
while immediate process termination preserves its backing bytes until
the operating system reclaims the process. Tests inject both allocation and
unexpected exceptions after
`EmbeddedZip` registration, after ResourceGroup/ArchiveManager insertion, and
immediately before pointer-bound state publication. Teardown removes/unloads
each unique authenticated location, verifies its ArchiveManager entry is gone,
explicitly erases the idempotent EmbeddedZip factory entry, and only then drops
its immutable owner. `resourceRemove()` removes only a matching
pointer/handle/group/name tuple.

The pinned OGRE 14.5.2 recipe patches `ArchiveManager::load()` so a null
factory result, archive `load()` throw, map-allocation throw, or unexpected
duplicate insertion cannot strand a factory-owned archive. The exact creating
factory destroys every unpublished instance. The recipe test runs that rollback
twice and all Linux x86_64, macOS arm64, and Windows x86_64 locks pin the patched
recipe revision.

Within one active generation, a duplicate pointer/token, a handle collision, or
live pointer reuse fails closed. Reload is accepted only for the same exact
source identity and bytes when the resource state count strictly increases.
After exact removal or a newer group generation, the pointer may be reused.

## Verification

`Ogre14AuthenticatedTextureReceiptTests` covers SHA-256, immutable replacement
bytes, legacy and DX10 DDS facts, generated-rule provenance, caps, exact-member
and case collisions, stale generations, downstream-failure retry, reload,
pointer reuse, resource removal, group reset/teardown, pre-resource tokens,
non-forgeable loaded resolutions, exact `n + 1` state, resolver and registry
substitution, unrelated-snapshot invalidation/fresh resolve, exact owner
preservation, and allocation/unexpected exception rollback. The pinned native
extractor test adds real `Resource::load()`/`reload()` state transitions,
readable RGBA texture capture, final resolver revalidation, untextured and
legacy behavior, teardown invalidation, and transactional output invariance.
Mount tests cover all three external
side-effect boundaries, prior-map/generation/accounting preservation, and
manager/factory/immutable-owner teardown. Terrain verifier tests cover
same-bytes hashing, immutable ownership, cap failure, and failed replacement
rollback. The contract test proves the ContentManager wiring, patched recipe,
three target locks, CI target, and N2 source provenance stay in closure.
This gate reaches authenticated OGRE-native material capture. It is
not live Ogre-Next material consumption, scene wiring, or a visual-fidelity
claim.
