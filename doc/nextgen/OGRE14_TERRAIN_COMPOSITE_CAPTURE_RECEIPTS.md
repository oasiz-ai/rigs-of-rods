# OGRE 14 terrain-composite capture receipts

## Scope

This prerequisite captures the exact level-zero composite texture generated by
one loaded OGRE 14 TerrainGroup slot. It does not wire the capture into
`GfxScene`, select an Ogre-Next material, or claim that CityWorld already
renders through the captured texture.

The native edge is pinned to OGRE 14.5.2 and must run on OGRE's serialized
render/resource thread while TerrainGroup slot, Terrain, Texture, and resource
lifecycle mutation are excluded. Pinned OGRE exposes a non-atomic Resource
state counter; concurrent reload/readback is deliberately unsupported.

## Exact patched API

The pinned recipe applies
`cmake/conan/recipes/ogre3d/patches/14.5.2/terrain-composite-revision-metal-readback.patch`.
That patch provides the authority used here:

- `Terrain::updateCompositeMap()` calls the material generator's synchronous
  RTT update and calls `mCompositeMap->_dirtyState()` only after the RTT
  returns successfully;
- initial black or cached composite upload also calls `_dirtyState()`, so a
  usable composite texture has a nonzero content revision;
- Metal level dimensions use the dimensions already supplied by
  `Texture::createSurfaceList`, level-zero uploads regenerate automatic mips,
  and readback honors the selected face and mip;
- private Metal storage copies to a shared staging buffer and stalls before
  CPU access; directly readable storage also stalls; and
- `PixelUtil::bulkPixelConversion` converts to the requested destination
  format without a Metal-only vertical flip.

`Ogre14TerrainCompositeNativeAdapter::Capture` performs this exact sequence:

1. authenticate the signed TerrainGroup slot, packed key, slot object, and
   Terrain pointer;
2. reject an unloaded page or active derived-data update;
3. invoke `Terrain::updateCompositeMap()` (not the delayed update);
4. acquire the exact `Texture` and level-zero `HardwarePixelBuffer`;
5. capture all native identity and state, including a nonzero Resource
   revision;
6. allocate a capped, tight `width * height * 4` destination and call
   `HardwarePixelBuffer::blitToMemory` with `PF_BYTE_RGBA`;
7. reacquire the group slot, Terrain, Texture, and pixel buffer and require all
   identity, dimensions, format, state, and Resource revision observations to
   be identical; and
8. compute SHA-256 and publish one immutable owner only after all fallible work
   succeeds.

No resource name is authority by itself. The receipt binds the TerrainGroup,
TerrainSlot, Terrain, Texture, and pixel-buffer pointer tokens; signed slot
coordinates and packed key; the exact current `TerrainSlotDefinition` kind,
optional definition filename or live `ImportData` pointer, and separately
labeled generated save filename; Terrain layout, position, loaded state, and
derived-update state;
texture pointer, handle, group, name, type, usage, loading/manual/gamma state;
format, dimensions, face, mip, and tight pitches; and the stable Resource
revision observed on both sides of readback.

OGRE frees `ImportData` after a successful imported-page prepare. When the
slot definition is consequently empty, the receipt records
`CONSUMED_OR_RUNTIME` and preserves only the current page identity. It does not
claim that `TerrainGroup::generateFilename()` was the historical load source;
that value is retained solely as `generated_save_filename`.

## Lossless bytes and bounds

The retained bytes are tight `PF_BYTE_RGBA` bytes. Row zero is the first row
returned by OGRE's PixelBox API, and no adapter or backend-specific flip is
performed. Destination format, not host integer endianness, defines the
retained byte order as red, green, blue, alpha.

Default limits are 8192 pixels per axis, 256 MiB of RGBA data, and 16 KiB per
identifier. Hard limits are 16384 pixels, 1 GiB, and 64 KiB. Multiplication is
checked before cap comparison or allocation, and the native adapter also
rejects a slice that cannot fit `size_t`.

The receipt is default-empty and its nonempty constructor is private. Copies
share the exact immutable control block. Bad allocation, OGRE exceptions,
unexpected exceptions, cap failures, stale revisions, and native substitution
leave the caller's prior receipt and its metadata/byte pointers unchanged.
The synthetic entry point and its already-defined test authority exist only
when `ROR_OGRE14_TERRAIN_COMPOSITE_CAPTURE_INTERNAL_TESTING` is compiled into
every translation unit of a dedicated test executable. Production builds have
neither that entry point nor a caller-definable friend seam; only the exact
native adapter can mint a nonempty receipt.

## Exact channel semantics and lowering blocker

OGRE 14's Terrain component serializes this map as three diffuse channels plus
one specular-mask channel. `TerrainMaterialGeneratorA` blends each layer's
albedo/specular texture into RGBA, where alpha carries the per-layer linear
specular mask. The capture therefore preserves every alpha byte and labels it
`LINEAR_SPECULAR_MASK`; it never reinterprets alpha as transparency.

The renderer-neutral `MaterialDescriptor` cannot currently represent this
exact contract:

- a base-color texture interprets alpha as coverage for OPAQUE, MASK, or
  straight-alpha BLEND; and
- metallic/roughness PBR has no independently bound legacy specular-mask
  channel or OGRE Terrain specular response.

Consequently
`ValidateOgre14TerrainCompositeMaterialDescriptorLowering` returns the stable
`terrain_composite.material_descriptor.alpha_specular_mask` semantic blocker.
Neither UNLIT nor PBR lowering is claimed. A future descriptor extension must
define and implement the legacy specular-mask response before this gate can be
removed.

## Cross-platform validation

The receipt implementation is renderer-neutral C++17. The native adapter uses
only public OGRE Main/Terrain APIs and contains no Metal, D3D11, or GL headers,
so the same source compiles for macOS, Windows, and Linux. Synthetic tests cover
all authority, cap, overflow, layout, SHA-256, semantic-blocker, and rollback
paths. A separately linked pinned-OGRE test exercises the real public ABI,
`PixelBox`, and `PixelUtil` conversion behavior through a synthetic
CPU `HardwarePixelBuffer` override, and compiles the complete Terrain adapter
on macOS arm64. It does not exercise Metal or another backend pixel-buffer
implementation. That focused probe is not a live CityWorld GPU/RTT acceptance
claim.
